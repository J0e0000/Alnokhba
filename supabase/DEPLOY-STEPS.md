# النخبة — خطوات التركيب النهائية (إصدار إصلاح خطأ النشر)

## 📦 المحتوى (ملف واحد جديد بكل الإصلاحات)

| الملف | وظيفته |
|------|--------|
| `NOKHBA-FINAL.zip` | الواجهة كاملة (كل جولات الإصلاق 1-8 + إصلاحات الجولة النهائية + إصلاح خطأ النشر) |
| `supabase/migrations/migration_041_master_fix_all.sql` | الملف الرئيسي الموحّد (بديل migration_040 — بيشمل كل الإصلاحات + إصلاح خطأ 42P13) |

## ⚠️ لو migration_040 ضرب معاك خطأ النشر ده

```
ERROR: 42P13: cannot change return type of existing function
HINT: Use DROP FUNCTION upsert_lesson_attendance(uuid,uuid,text) first.
```

**السبب**: الدوال القديمة على قاعدة بياناتك ليها نوع إرجاع قديم، وPostgreSQL
مش بيسمح لـ `CREATE OR REPLACE` يغيّر نوع الإرجاع — لازم الدالة تُسقَط الأول.

**الحل موجود جوّه `migration_041_master_fix_all.sql`**: الجزء الأول من الملف
بيعمل السقوط ده تلقائيًا وبأمان قبل إعادة البناء. شغّل الملف ده بس —
ومتشتغلش migration_040 خالص (ملف 041 شامل كل اللي فيه + الإصلاح).
الملف آمن حتى لو جزء من 040 اشتغل قبل كده — كله idempotent.

---

## ✅ خطوة 1 — شغّل ملف الـ SQL الجديد (الملف الوحيد المطلوب)

افتح **Supabase → SQL Editor → New query**، الصق محتوى
`supabase/migrations/migration_041_master_fix_all.sql` كاملاً، واضغط **Run**.

الملف بيصلّح:

1. **خطأ النشر 42P13**: بيسقط الدوال الثلاثة القديمة بأمان ويعيد بنائها
   بنفس التواقيع بالظبط (الواجهة مش محتاجة أي تعديل).
2. **مشكلة «تعذر حفظ حضور الطالب ده»**: كان فيه قيد قديم «سجل حضور واحد
   لليوم» بيمنع تسجيل حضور/غياب حصة تانية لنفس الطالب في نفس اليوم. الملف
   بيشيل القيد ده وبيعمل فهرس فريد جديد (سجل واحد لكل طالب × حصة) — تقدر
   تسجّل عشر حصص في اليوم عادي.
3. بيحافظ على كل تاريخ الحضور القديم (مبيمسحش أي سجل ليوم مختلف).
4. آمن لإعادة التشغيل أي عدد من المرات (كل الأوامر idempotent).
5. مش محتاج أي migration قديم — ده آخر ملف مطلوب.

⚠️ لو ظهرلك تحذير أصفر في النتيجة (WARNING) بعد التشغيل — اقراه بس، مش خطأ:
ده فحص ذاتي بيطمن إن مفيش قيد «سجل واحد لليوم» رجع تاني.

## ✅ خطوة 2 — ارفع الواجهة الجديدة (نفس طريقتك المعتادة)

فك ضغط `NOKHBA-FINAL.zip` وارفعها على Vercel بدل القديمة (أو أي استضافة
بتستخدمها) — الخصائص الجديدة:

1. **iOS / الآيفون اشتغل نهائيًا** (الموقع + بوابة الطالب):
   - البناء الجديد مستهدف أقدم أجهزة (iOS 11+ للكود و iOS 13+ للستايلات).
   - الـ CSS اتحوّل لصيغة قديمة آمنة: كل `color-mix()` و `oklch()` بقت ليها
     بدائل ثابتة تشتغل على أي آيفون — دي كانت **سبب الصفحة البيضاء**.
   - شاشة تحميل فورية + لو حصل أي مشكلة تظهر رسالة عربية واضحة بدل الصفحة
     الفاضية.
2. **شريط البحث رجع لعدّاد الدرجات (دفتر الدرجات)**: ابحث بالاسم / الكود /
   الهاتف / اسم الامتحان، مع كروت الناجحين والفاشلين ونسبة النجاح، وجدول
   نتايج كل طالب.
   - وكمان: بحث جوّه «كل الامتحانات» + بحث فوق قائمة طلاب الحصة.
3. **رسائل الخطأ بقت تقول السبب**: لو الحفظ فشل هتشوف «السبب: ...» — ولو
   لسه شغال من غير ملف الـ SQL هيقولك عليه بالظبط.

بعد الرفع: **Advise طلابك يمسحوا كاش المتصفح أو يفتحوا الرابط من جديد**
(أول زيارة هتاخد ثانية زيادة بس).

## 📧 رسالة Supabase عن البريد المرتد (Bounce Rate Warning)

الرسالة دي معناها: نسبة الإيميلات المرتدة (Bounced) من إيميلات النظام عالية.
إيميلات النظام عندهم بتستخدم في حاجتين بس: تأكيد إنشاء الحساب + استعادة كلمة
المرور. أسبابها الشائعة:

1. **حسابات تجريبية بإيميلات وهمية** (زي test@test.com) — امسحها:
   Supabase → Authentication → Users → دور على المستخدمين بإيميلات غلط
   وامسحهم.
2. **طلاب/مدرسين كتبوا إيميل غلط وقت التسجيل**.
3. لو مش محتاج تأكيد الإيميل أساسًا: Authentication → Sign In / Providers →
   Email → اقفل «Confirm email» — كده مفيش إيميلات بتتبعت خالص للمستخدمين
   الجدد.

**الحل الدائم (اختياري بس مستحسن)**: اضبط SMTP خاص بيك من
Authentication → Emails → SMTP Settings — استخدم خدمة مجانية زي Brevo
(300 إيميل/يوم مجانًا) أو Resend — كده تبعت من دومينك ومفيش قيود
Supabase ولا رسايل تحذير.

> ملاحظة: إشعارات المنصة نفسها (اللي بتوصل للطلاب) بتشتغل عبر Web Push
> مش بريد — عمرها ما بتأثر على التحذير ده.

## 🧪 بعد التركيب — اختبر في دقيقة

1. افتح حصة لمجموعة، سجّل حضور، **انهي الحصة**، افتح **حصة تانية** لنفس
   المجموعة في نفس اليوم، وسجّل حضور — لازم يتسجل عادي بدون أي رسالة خطأ.
2. افتح تاب **دفتر الدرجات** — لازم تشوف شريط البحث + كروت الناجحين/الفاشلين.
3. افتح رابط طالب (QR) من **آيفون** — لازم تظهر شاشة النخبة وبيانات الطالب
   بالألوان كاملة (مش صفحة بيضاء). جرّبها كمان من آيفون قديم لو متاح.
